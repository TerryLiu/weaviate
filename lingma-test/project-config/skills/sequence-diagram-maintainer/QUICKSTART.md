# 时序图技能快速开始

## 📋 前置条件

- 已安装 `sequence-diagram-maintainer` 技能
- 项目根目录存在 `diagrams/` 文件夹

## 🚀 快速上手

### 1. 查看现有时序图

```bash
cat diagrams/data-flow.md
```

或在支持 Mermaid 的编辑器中打开查看渲染效果。

### 2. 更新时序图

**方式一: 添加新组件**

告诉 AI:
```
使用时序图技能,在 data-flow.md 中添加一个新的备份服务:
- API网关 -> 备份服务: 触发备份
- 备份服务 -> 存储层: 读取数据
- 备份服务 -> S3: 上传备份
- 备份服务 -> API网关: 返回备份状态
```

**方式二: 修改现有流程**

```
修改时序图中的认证流程,添加 OAuth2 支持:
- 客户端先请求授权码
- 认证服务返回授权URL
- 客户端重定向到OAuth提供商
- 认证成功后回调认证服务
- 认证服务颁发token
```

**方式三: 创建新的时序图**

```
为 Raft 共识算法创建一个详细的时序图,保存到 diagrams/raft-consensus.md
```

### 3. 验证时序图

使用在线工具验证生成的 Mermaid 代码:
- 访问 https://mermaid.live/
- 复制时序图代码粘贴进去
- 检查渲染效果是否正确

## 💡 常用示例

### 示例 1: 简单的三层架构

```
创建时序图展示三层架构:
客户端 -> Web服务器: HTTP请求
Web服务器 -> 应用服务器: 业务逻辑处理
应用服务器 -> 数据库: SQL查询
数据库 -> 应用服务器: 返回结果
应用服务器 -> Web服务器: 响应数据
Web服务器 -> 客户端: HTML页面
```

### 示例 2: 微服务调用链

```
添加微服务调用链:
API网关 -> 用户服务: 获取用户信息
用户服务 -> 缓存: 查询用户缓存
alt 缓存命中
    缓存 -> 用户服务: 返回缓存数据
else 缓存未命中
    用户服务 -> 数据库: 查询用户
    数据库 -> 用户服务: 返回用户数据
    用户服务 -> 缓存: 更新缓存
end
用户服务 -> API网关: 返回用户信息
```

### 示例 3: 异步消息队列

```
添加消息队列流程:
生产者 -> 消息队列: 发布消息
消息队列 -> 消费者1: 推送消息
消息队列 -> 消费者2: 推送消息
消费者1 -> 消息队列: 确认消费
消费者2 -> 消息队列: 确认消费
```

## 🎯 最佳实践

### ✅ 推荐做法

1. **保持简洁**: 每个参与者使用 2-4 个字符的别名
2. **明确流向**: 从左到右按调用顺序排列参与者
3. **使用激活框**: 清晰显示组件的活跃时间段
4. **添加注释**: 复杂逻辑使用 Note 说明
5. **版本管理**: 每次更新都记录变更历史

### ❌ 避免事项

1. **不要过度详细**: 避免展示每一行代码级别的交互
2. **不要交叉混乱**: 合理安排参与者顺序,减少消息线交叉
3. **不要忘记配对**: activate 必须有对应的 deactivate
4. **不要忽略错误**: 重要的错误处理流程应该包含
5. **不要硬编码**: 使用通用名称而非具体实例名

## 🔧 高级技巧

### 技巧 1: 分组相关组件

使用注释将相关组件分组:

```mermaid
%% 客户端层
participant Client as 客户端

%% API层
participant API as API网关
participant Auth as 认证服务

%% 业务层
participant Service as 业务服务
```

### 技巧 2: 表示并行处理

```mermaid
par 并行执行
    A->>B: 任务1
and
    A->>C: 任务2
end
```

### 技巧 3: 循环和批处理

```mermaid
loop 处理每条记录
    Processor->>DB: 插入数据
    DB-->>Processor: 确认
end
```

### 技巧 4: 可选流程

```mermaid
opt 缓存启用
    Service->>Cache: 查询缓存
    Cache-->>Service: 返回缓存
end
```

## 🐛 常见问题

### Q1: 时序图太大无法渲染?

**A:** 拆分为多个子图:
- 主图展示高层架构
- 子图展示详细流程
- 使用链接关联相关图表

### Q2: 如何表示超时和重试?

**A:** 使用 alt 块:

```mermaid
alt 首次尝试成功
    A->>B: 请求
    B-->>A: 响应
else 超时重试
    A->>B: 重试请求
    B-->>A: 响应
end
```

### Q3: 如何展示内部实现细节?

**A:** 使用 participant 的自调用:

```mermaid
participant Service as 服务
Service->>Service: 内部处理
Note right of Service: 详细逻辑说明
```

### Q4: 多人协作时如何处理冲突?

**A:** 
1. 使用 Git 进行版本控制
2. 每次更新添加明确的变更说明
3. 定期合并和解决冲突
4. 保留历史版本以便追溯
