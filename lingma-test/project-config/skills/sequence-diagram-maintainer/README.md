# Sequence Diagram Maintainer Skill

## 概述

这是一个专业的时序图维护技能,用于根据对象关系自动更新和维护 Weaviate 项目的数据流时序图。

## 功能特性

- ✅ **智能解析**: 理解组件间的交互关系和数据流向
- ✅ **Mermaid 语法**: 使用标准的 Mermaid 时序图语法
- ✅ **增量更新**: 智能合并新旧关系,保留现有内容
- ✅ **最佳实践**: 遵循时序图绘制的行业标准和规范
- ✅ **质量保证**: 内置检查清单确保图表质量

## 使用方法

### 基本用法

直接描述需要添加或修改的对象关系:

```
帮我更新时序图,添加以下交互:
客户端 -> API网关: 发送请求
API网关 -> 认证服务: 验证token
认证服务 -> API网关: 返回结果
API网关 -> 业务服务: 转发请求
```

### 增量更新

在现有时序图基础上添加新组件:

```
在时序图中添加缓存层:
- 业务服务先查询缓存
- 缓存命中则直接返回
- 未命中则查询数据库并更新缓存
```

### 创建新时序图

为特定模块创建独立的时序图:

```
为 Raft 共识模块创建一个详细的时序图,展示:
1. Leader选举过程
2. 日志复制流程
3. 快照同步机制
```

## 输出位置

所有时序图保存在 `diagrams/` 目录:

- `data-flow.md` - 主数据流时序图(默认)
- 其他自定义时序图可根据需要创建

## 示例场景

### 场景 1: 添加新的微服务

**输入:**
```
添加一个搜索服务:
API网关 -> 搜索服务: 转发搜索请求
搜索服务 -> 向量索引: 执行向量搜索
搜索服务 -> 全文检索: 执行BM25搜索
搜索服务 -> API网关: 合并结果返回
```

**输出:**
自动在时序图中插入 Search 参与者,并添加相应的交互消息。

### 场景 2: 细化现有流程

**输入:**
```
展开 AI模块 的内部流程:
AI模块 -> Tokenizer: 文本分词
Tokenizer -> Embedding模型: 生成向量
Embedding模型 -> AI模块: 返回向量
```

**输出:**
将 Modules 参与者展开为子序列,显示内部组件交互。

### 场景 3: 添加错误处理

**输入:**
```
为数据库查询添加错误处理:
如果查询超时,返回超时错误
如果连接失败,尝试重连3次
重连失败后返回服务不可用
```

**输出:**
使用 `alt` 块添加成功和失败的分支流程。

## 时序图规范

### 参与者命名

- 使用简洁的别名(2-4个大写字母)
- 完整名称使用中文或清晰的英文
- 示例: `participant API as API网关`

### 消息类型

- 同步调用: `->>` (实线箭头)
- 异步消息: `->` (实线无箭头)
- 返回消息: `-->>` (虚线箭头)

### 激活框

始终配对使用:
```mermaid
activate 组件名
...交互...
deactivate 组件名
```

## 维护指南

### 何时更新

- 新增系统组件或服务
- 修改组件间交互方式
- 调整数据流向
- 优化架构设计后

### 更新频率

建议每次重大架构变更后立即更新,保持时序图与实际架构同步。

### 版本控制

- 每次更新都要在"更新历史"中记录
- 包含更新日期、变更内容和操作人
- Git 提交时提供清晰的 commit message

## 质量保证

## 故障排除

### 问题: 时序图无法渲染

**解决方案:**
1. 检查 Mermaid 语法是否正确
2. 使用 Mermaid Live Editor 验证
3. 确保所有 activate/deactivate 配对
4. 检查参与者是否都已声明

### 问题: 时序图过于复杂

**解决方案:**
1. 拆分为多个子时序图
2. 使用 Note 简化复杂逻辑描述
3. 提取公共流程为独立图表
4. 降低细节层级,聚焦关键路径

### 问题: 更新冲突

**解决方案:**
1. 优先保留用户明确要求的变更
2. 对于不确定的部分,向用户确认
3. 提供多个方案供用户选择
4. 保留备份以便回滚
